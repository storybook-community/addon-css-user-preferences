# CSS User Preferences

Emulate the `prefers-*` CSS user preferences in Storybook, so you can see how a
component responds to dark mode, reduced motion, or reduced data without
changing your operating system settings.

## What makes it different

Most preference addons toggle a class on the root element, which means your CSS
has to be written for the addon:

```css
/* only works while the addon is driving it */
.dark .button { background: black; }
```

This addon rewrites the `@media` conditions in the live CSSOM instead. Your own
rules stay exactly as you wrote them, and the ones that fire are the ones you
actually ship:

```css
/* unchanged, and still what gets tested */
@media (prefers-color-scheme: dark) {
  .button { background: black; }
}
```

Picking **dark** rewrites that condition to `all`, so the rule applies. Picking
**light** rewrites it to `not all`, so it is switched off rather than merely
unmatched. Conditions for preferences you have not set are left untouched.

### What the CSSOM is

The CSS Object Model is the browser's own parsed form of every stylesheet on the
page — the same objects it consults to decide what each element looks like, not
a copy kept alongside them. JavaScript reaches it through `document.styleSheets`:
each sheet exposes a `cssRules` list, and every `@media` block in that list is a
`CSSMediaRule` whose condition is readable and writable as `media.mediaText`.

Writing to that property is not a request the browser gets to defer. It
re-evaluates the rule and restyles the page immediately, with no reload and no
re-parsing of your source. Nothing is injected and no selector is touched, so
the outcome is indistinguishable from your stylesheet having asked for that
condition itself — which is why a component under emulation behaves the way it
will in front of a real reader.

That is the entire mechanism. The addon walks `document.styleSheets`, descends
into nested rules, and for each `CSSMediaRule` mentioning a `prefers-*` feature
swaps the condition for `all` or `not all`. It remembers each rule's original
condition text, so every toggle rewrites from what you wrote rather than from
the previous rewrite.

See [How it works](?path=/story/how-it-works-rewriting-conditions--rules) for the
full rewriting table, computed live.

### JavaScript reads the same preference

The CSSOM is only half of what a component consults. A `useMediaQuery` hook, a
theme library resolving its initial theme, a reduced-motion check that gates an
animation in JavaScript — all of them ask `window.matchMedia`, which the CSSOM
rewrite does not reach. Left alone, they would keep reporting the real operating
system value while the CSS around them was emulated.

So while a preference is being emulated, `window.matchMedia` is patched as well.
A query naming an emulated feature is answered with the emulated result, and the
`MediaQueryList` it returns dispatches a `change` event when the toolbar changes
a preference, so a subscriber follows the toolbar rather than going quietly
stale. Everything else — an unset preference, a viewport condition, the rest of
a compound query — is still the browser's own answer, and a query shape the
addon cannot express falls back to the real value rather than guessing.

Returning every preference to its system default puts the browser's own function
back, so a Storybook that is not emulating anything is untouched. See
[Emulating matchMedia](?path=/story/how-it-works-emulating-matchmedia--in-javascript).

## Install

```sh
pnpm add -D @storybook-community/addon-css-user-preferences
```

See [Installation](?path=/docs/installation--docs) for registering it and for
the other entry points.

## Use it

Pick a preference from the toolbar and the preview updates. To pin one for a
single story, set the parameter:

```ts
import { defineCssUserPrefsParam } from '@storybook-community/addon-css-user-preferences'

export const DarkOnly = meta.story({
  parameters: defineCssUserPrefsParam({ 'prefers-color-scheme': 'dark' }),
})
```

The toolbar still wins if a reader picks a value themselves, so the parameter
acts as a default rather than a lock.

See [Usage](?path=/story/usage-emulating-preferences--from-the-toolbar) for
working examples, and [Supported preferences](?path=/story/usage-supported-preferences--table)
for every feature and value.
